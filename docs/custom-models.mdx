BibGenie includes [official models](/docs/models) optimized for reading and understanding papers and using research tools, balancing quality and value. Start AI paper reading in Zotero without configuring an API key.

If research data privacy is a priority, or you want to use an existing model service, **custom models** let you connect your own API key (BYOK), institutional services, or local models through Ollama and LM Studio, directing model requests to the service you specify.

BYOK means **Bring Your Own Key**: use your own provider credentials instead of BibGenie's official model service. You can also connect an institutional endpoint or a local service that does not require an API key. Use this page to set up the connection, select the model, and understand where data and charges go.

The **Add Model** menu in Model Settings has two entries:

- **Add chat model**: configure a model for chat, paper reading, and tool calls.
- **Add Embedding model**: configure a model for semantic indexing and literature search.

## Is a Custom Model Right for You?

Official models need no API-key setup. Configure a custom model if you:

- Already have a provider API account and want charges on that account.
- Need an institutional model service.
- Want local model computation for sensitive material.
- Need a model outside the official list.

## Before adding a model

For a cloud service, prepare the provider's **API Key, Model ID, and API address**.

For a local model, start the service, prepare the appropriate model, and confirm the service address and Model ID. Local services usually do not require an API key.

## Add a model

<Steps>
  <Step>
    **Open the add dialog.** Go to **Settings → Models (Model Settings)**. Under Custom Models, click **Add Model**, then choose the appropriate entry.
  </Step>
  <Step>
    **Enter the provider and model.** Search for a provider in **Provider ID**, then select a model in **Model ID**. Catalog entries fill in available names, connection settings, and model details. You can enter missing entries manually.
  </Step>
  <Step>
    **Check the connection.** Enter the API Key and check **Provider Type** and **Base URL** against the provider's requirements. **Model ID** is the identifier used by the API; **Model Name** is the name displayed in BibGenie.
  </Step>
  <Step>
    **Test and save.** Click **Test**, then **Add Model** after Connected appears. If the test fails, check the configuration using the error message. When adding an Embedding model, you can leave dimensions empty to detect them on test or save.
  </Step>
</Steps>

Expand these notes if you need to check the connection type or model parameters:

<Accordions>
  <Accordion title="Provider and API address">
    **Provider Type** determines the API integration BibGenie uses and must match the provider's interface. Set **Base URL** to the API address, keeping required paths such as `/v1`.

    | Connection | Provider Type | Base URL and Model ID |
    | :--- | :--- | :--- |
    | Cloud API | Match the provider's API type | Use the API address and model ID supplied by the provider |
    | Compatible API or proxy | Usually OpenAI Compatible; follow provider instructions | Use the corresponding API address and model ID |
    | Ollama | Ollama | Usually `http://localhost:11434`; use the actual name of an installed model as Model ID |
    | LM Studio | Usually OpenAI Compatible | Use the local API Server address, such as `http://localhost:1234/v1`, and the loaded model's actual ID |

    Embeddings currently support **OpenAI, Google, OpenAI Compatible, OpenRouter, and Ollama**. The specific model must also support embeddings; local services need an embedding model prepared as well.
  </Accordion>
  <Accordion title="Chat model capabilities and length limits">
    Set **Model Types** according to the model's actual capabilities:

    - **Text**: text chat.
    - **Vision**: image input.
    - **Reasoning**: reasoning capability.
    - **Function Calling**: tool calls used in reading, search, and library tasks.
    - **Web Search**: web search provided by the model service itself.

    **Context Window** is the context length; **Max Tokens** is the output limit per request. After catalog completion, check these values against the capabilities and limits your provider actually offers.
  </Accordion>
  <Accordion title="Embedding dimensions">
    Leave dimensions empty when adding a model to detect them on Test or save. Detection must succeed before saving. Alternatively, enter a positive integer matching the model's native output vector length. This field checks output length; it does not request dimensionality reduction.

    If you enter dimensions manually, you can save directly. Testing first is still recommended to check both connectivity and dimensions.
  </Accordion>
  <Accordion title="Supported chat providers">
    Chat models support OpenAI, Anthropic, xAI, DeepSeek, Google, Groq, Moonshot AI, OpenRouter, Ollama, and OpenAI Compatible. LM Studio normally uses OpenAI Compatible. Choose the integration that matches the service's actual API; a provider name alone does not guarantee that every model supports images or tools.
  </Accordion>
</Accordions>

## Use your added model

### Chat model

Make sure the model is enabled in Model Settings, then return to the chat page and select it in the model selector.

To use it by default in new conversations, go to **Settings → Chat Settings → Default Model** and select it from the dropdown. Only enabled chat models appear here.

### Embedding model

Enable the model, then select it in **Settings → Library & Index → Semantic Index → Embedding Model**.

If a confirmation appears, click **Switch and rebuild**. BibGenie regenerates the semantic index for included libraries without changing your original items. Rebuilding can take time and incur provider charges. See [Semantic Index](/docs/semantic-index) for index status and retrying failures.

## Data and API Key Storage

Custom model requests go directly from the local Zotero plugin to the service you configure, **without passing through BibGenie's model service**. Your **API key and model connection settings are stored locally in Zotero and are not uploaded to BibGenie servers**.

| Model purpose | What the service receives | Where you choose it |
| :--- | :--- | :--- |
| Chat | Conversation content and paper context needed for the task | Chat page or Default Model in Chat Settings |
| Embedding | Titles and abstracts for indexing, plus semantic search queries | Embedding Model in Library & Index |

Chat and embeddings are independent. Choosing a custom chat model does not reroute an official embedding model. A compatible API or proxy receives requests at your configured Base URL; a cloud provider still receives the content needed for its model. Choose the service according to your research data requirements and its own terms.

For local computation, run Ollama or LM Studio on your computer and keep the service available. If you want both chat and embedding computation local, prepare and select a local model for each purpose. A locally stored semantic index alone does not mean its vectors were generated locally. Web search and connected services have their own data routes.

### Examples of Request Destinations

| Configuration | Where the model request goes |
| :--- | :--- |
| OpenAI or Anthropic with that provider’s API address | Directly to the configured provider |
| OpenAI Compatible proxy or institutional service | To the configured Base URL; the operator of that service receives the request |
| Ollama or LM Studio running on this computer | To that local service for model computation |

An API key alone does not determine the destination: check the Base URL. Apply this choice separately to chat and embeddings; local model computation does not make web tools local.

## Costs and BibGenie Credits

Custom chat and embedding requests do not consume BibGenie's **model credits**. A cloud provider may charge your provider account; local models use your computer's resources. Building or rebuilding an index and running semantic queries may incur embedding-provider charges.

External tools still follow your BibGenie plan's separate charging rules. A separately selected official chat or embedding model also keeps its official billing rules. See [Pricing & Credits](/docs/pricing-credits) for those distinctions.

## Common questions

<Accordions>
  <Accordion title="Why can't I find my saved model?">
    Check that the model is enabled and look in the right place: select chat models on the chat page or in Default Model settings, and embedding models in Library & Index.
  </Accordion>
  <Accordion title="What should I check when Test fails?">
    Use the error message to check API Key, Base URL, Provider Type, and Model ID. Confirm the provider account is usable and the model supports the selected purpose. For local services, check that the service is running, the model is installed or loaded, and the port is correct.

    If embedding dimensions do not match, check the model's native output dimensions.
  </Accordion>
  <Accordion title="How do I edit, disable, or delete a model?">
    Click a custom model card to edit it, use the switch to enable or disable it, or use the delete button. The default chat model and current embedding model cannot be disabled or deleted; select another model first.

    You can edit the current embedding model's name, description, and API key without rebuilding. Other settings are locked while in use. Switch to another embedding model before changing the address, model, or dimensions. After updating a key, retry previous indexing failures with **Retry Failed** in Semantic Index.
  </Accordion>
  <Accordion title="How are custom models billed, and where is data sent?">
    The selected custom model receives requests directly from Zotero. Its model requests do not use BibGenie model credits, but provider fees and the plan's external-tool charges may still apply. The data table above distinguishes chat content from embedding text; use the provider's terms when assessing sensitive material.
  </Accordion>
  <Accordion title="Does a local chat model also make semantic search local?">
    Chat and embeddings use separately configured models. To process both types of model requests on your computer, add and select local chat and local embedding models separately.
  </Accordion>
</Accordions>
