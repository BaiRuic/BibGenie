BibGenie supports two kinds of models: **official models** and **custom models**.

- Official models are maintained by BibGenie and work out of the box. You do not need to configure your own API key.
- Custom models are configured by you, including the provider, Base URL, API key, and model capabilities.

You can manage both from **Model Settings**.

## What Do You Need to Choose?

For your first conversation, start with the built-in chat model. You can choose another model later when a task needs a different capability or data route.

| Need | What to choose or check |
| :--- | :--- |
| Ask questions, summarize, or compare papers | A chat model; built-in models avoid API setup |
| Find library papers by meaning | An embedding model, selected separately in Library & Index |
| Ask about a screenshot, figure, or scanned page | A chat model that accepts image input |
| Let the agent search, read, or organize with tools | A chat model that supports tool use |
| Use an existing provider account or a local model | A [custom model](/docs/custom-models); see [Custom and Local Models](/docs/custom-models) for data routes and billing |

Changing the chat model does not change the embedding model. If you want both types of model requests to stay local, configure and select local models for both purposes.

## Official Models

Official models are configured by BibGenie for research tasks such as:

- Long-context paper reading
- Multi-paper comparison
- Complex research reasoning
- Tool calling and structured output
- Multimodal inputs such as figures, formulas, and screenshots
- Accurate answers grounded in Zotero context

Provider configuration also matters. The same model can behave very differently across providers because of context limits, tool-calling support, rate limits, parameter defaults, and network reliability.

To reduce configuration work for users, BibGenie does several things:

<Steps>
  <Step>
    We test selected models on paper reading, literature search, library management, and note-taking workflows.
  </Step>
  <Step>
    When possible, we discuss recommended deployment and usage patterns with model or provider teams.
  </Step>
  <Step>
    We work with selected providers so models are served in ways that work well with BibGenie.
  </Step>
  <Step>
    We benchmark model-provider combinations and maintain a recommended list.
  </Step>
</Steps>

You do not need your own API key for official models. Check the available list in Model Settings and use the guidance below when choosing among them.

## Custom Models

If you have your own API key or want to use a local model, you can add a custom model.

Custom models are useful when:

- You already pay for a provider such as OpenAI, Anthropic, DeepSeek, or OpenRouter.
- Your institution requires requests to go directly to a specific provider.
- You want to use Ollama or LM Studio locally.
- You need a model that is not currently included in the official list.

See [Custom Models](/docs/custom-models) for setup instructions.

## What Do the Multipliers Mean?

You may see labels such as `0x`, `1.5x`, or `2x` after a model name.

These labels indicate the approximate speed at which the model may consume credits:

| Label | Meaning |
| :--- | :--- |
| `1x` | Standard consumption speed. |
| `1.5x` | May consume credits faster than a standard model for a similar task. |
| `2x` or higher | Usually indicates a higher-cost model, best reserved for more demanding tasks. |

<Callout type="info" title="Actual usage depends on tokens and model pricing">
  Multipliers are shown as a user-facing hint. Actual credit usage is calculated from input tokens, output tokens, model pricing, and tool usage.
</Callout>

## Refreshing the Model List

The official model list refreshes automatically. You can also refresh it manually:

<Steps>
  <Step>
    Open BibGenie.
  </Step>
  <Step>
    Go to **Model Settings**.
  </Step>
  <Step>
    Click **Refresh** in the official models section.
  </Step>
</Steps>

If a model is missing, possible reasons include:

- Your plugin version is out of date.
- The model list has not refreshed yet.
- The model is temporarily unavailable or being adjusted.
- Your account status has not synced.

## Choosing a Model

<Cards>
  <Card title="Translation and short Q&A">
    Start with an official model with a low multiplier.
  </Card>
  <Card title="Single-paper summaries">
    Use an official model with reliable context handling and strong output quality.
  </Card>
  <Card title="Complex reasoning and reviews">
    Use a model with stronger reasoning ability and a longer context window.
  </Card>
  <Card title="Privacy or local execution">

  </Card>

## Data and Credit Questions

<Accordions>
<Accordion title="Does my paper leave this device?">

When you use an official model, the prompt and necessary paper context pass through BibGenie’s service to its model provider. Custom model requests go directly to the service you configure; a cloud provider still receives that content. Local chat and local embedding models must be selected separately if you want both kinds of model computation to stay on your device. Web search and connected services have their own data routes. See [Custom and Local Models](/docs/custom-models).

</Accordion>
<Accordion title="Is my library used to train models?">

BibGenie’s [Privacy Policy](/privacy) states that BibGenie does not use your Zotero library, local files, local chat history, or BYOK keys to train AI models. This is not a blanket promise about every model provider: check the terms and settings of the service you use, especially for unpublished or restricted material. A locally stored semantic index does not mean embedding generation is local; that depends on the selected embedding model.

</Accordion>
<Accordion title="Does using a local or custom model cost credits?">

Custom chat and embedding requests do not consume BibGenie model credits. Provider fees or local computation costs still apply. External tools follow your plan’s separate charging rules, and choosing a custom chat model does not change a separately selected official embedding model. See [Pricing & Credits](/docs/pricing-credits).

</Accordion>
<Accordion title="How many papers can my balance cover?">

There is no fixed paper count: length, model, follow-up questions, images, and tool steps all affect usage. Start with a focused question or a few relevant pages and check the recorded charge in Usage before a larger task.

</Accordion>
</Accordions>
